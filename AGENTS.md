NOTAM polygon geometry is stored in the existing `notam_schedule_windows[0]` object (`areaMode`, `polygon`), validated by `src/lib/notamGeometry.ts`; this keeps text and maps consistent without requiring a database migration.
Dropdown content and subcontent use Radix's available-height constraint and overridable collision padding for internal touch scrolling; popup callers must not lower the shared z-index, so sticky headers cannot cover menus.
SORA references use optional document IDs on mission types and missions; assess PDFs with the caller's RLS-scoped client and never equate a reference with an approved operating authorization, so departments inherit defaults without bypassing document access.
Mission risk badges use any non-null `mission_risk_assessments.sora_output` as the +SORA completion marker while keeping the latest assessment's score; this avoids conflating reassessment with `mission_sora` approval status.
Keep the active-flights dashboard list to one scroll-snapped flight per viewport with an in-header navigation arrow, so simultaneous flights never expand the dashboard row.
 - Never use `dvh` without a preceding `vh` fallback (e.g. `max-h-[90vh] max-h-[90dvh]`) and give touch scroll areas `[touch-action:pan-y]`; the DJI RC Pro runs Chromium 70, which ignores `dvh` and then loses scrolling. Fixed-height split-view dialogs size with `top/bottom` % insets (not `vh`), since old Chrome's `vh` includes the browser toolbar and pushes the dialog off-screen.
 - In portrait on screens ≤1024px wide (CSS media query, not UA detection), the flight-log split dialog stacks details above the list inside one flex-child scroller (`.dji-log-split`); the dialog itself stays `overflow-hidden`, matching the landscape panes that scroll reliably on DJI controllers, and it resets to the top when a log is selected. Landscape keeps the split panes.
Norwegian protected-area map classification comes from dronesoner.no's prohibition and observation GeoJSON feeds in the existing CAA zone store, not broad Naturbase protection forms; this prevents false prohibition labels while keeping one layer toggle.
- SORA containment (CAA 2.5 adjacent-area matrix) lives only in `supabase/functions/_shared/soraContainment.ts`, imported by the map and the edge function; the risk assessment recomputes it from `route.adjacentAreaDocumentation` with the assessment's SAIL and never maps SAIL→robustness, so map and assessment cannot drift.
- SORA document profiles: one row per document in `sora_document_profiles` (admin writes via RLS); schema, consistency check and register matching live only in `_shared/soraProfile.ts`, importing `_shared` SORA tables so numbers cannot drift. Register links (droneIds, catalogModelId, m2.equipmentIds) are set only by admins, never by AI.
- Envelope deviations block auto-approval (status unchanged; only a manual submission sets pending_approval) but never cause a hard stop or NO-GO; the risk assessment never writes approval_status — no notifications from the assessment.
- Code shared between edge functions lives in `supabase/functions/_shared/` (re-exported where needed), because each edge bundle includes only its own folder plus `_shared`.
- The mitigation preview reuses `_shared/soraProfileEvaluation.ts` through a frontend re-export, so profile credits shown before assessment follow the same deterministic conditions as the edge function.
- SORA profile dialog help and fields share the editor's single flex-child scroller; keep the header and action footer outside it so expanded help cannot hide the form or buttons.
- Compliance department filter and follow-up rate are presentation-only: rows carry companyId and are filtered/enriched in `audit/lib/complianceView.ts` before the scanner and score run, so validators and weights stay the single source of truth.
- Compliance "Open" buttons go through `AuditEntityDialogHost` (openEntity → existing detail dialogs over the module, invalidating ["audit"] on close); `auditDeepLink` is only for reminders and links missions via `/oppdrag?mission=`, which opens MissionDetailDialog — so leaders never lose their place and recipients land on the read-only card.
