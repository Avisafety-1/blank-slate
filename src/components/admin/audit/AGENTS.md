- Compliance department filter and follow-up rate are presentation-only: rows carry companyId and are filtered/enriched in `audit/lib/complianceView.ts` before the scanner and score run, so validators and weights stay the single source of truth.
- Compliance "Open" buttons go through `AuditEntityDialogHost` (openEntity → existing detail dialogs over the module, invalidating ["audit"] on close); `auditDeepLink` is only for reminders and links missions via `/oppdrag?mission=`, which opens MissionDetailDialog — so leaders never lose their place and recipients land on the read-only card.
- Internal audit templates live in `audit/lib/auditTemplates.ts` and are copied into `audit_sections`/`audit_checklist_items` by the `create_internal_audit` RPC; DB triggers set ownership, company, closed_by and verified_by server-side and lock closed reviews, so template edits never alter existing audits and clients cannot spoof audit trail fields.
- Internal audit close rules (unassessed items, deviations without justification, open critical findings) and finding self-verification are enforced in `audit_reviews_guard`/`audit_findings_guard`; the app only mirrors them via `closeBlockers`/`findingDisplayStatus` in `audit/lib/auditTemplates.ts`, so the server always decides.
